# After5 — MVP Reality-Reconciliation Audit

> Date: 2026-06-03. Read-only synthesis of 12 parallel category audits against the product vision: **"Swipe on the date, not the face."** Browse NIGHTS → match around the experience → host identity progressively reveals → every match already has a real plan attached. The AI date-planner is the moat. It is a two-sided dating MARKETPLACE.
>
> Thesis confirmed: the app was built **feature-first, not experience-first**. The core happy-path machinery (browse → swipe → interest → shortlist → offer → accept → lock) is real and well-built, but the surrounding marketplace — discoverability, host correction tools, the reveal ladder, the back half of the loop (date-happened → reviewed → trust), and the navigation graph that connects screens into a *product* — is missing, faked, or dead-ended. The app is currently a collection of strong screens, not a complete marketplace.

## Section A — Current reality (what actually exists, by area)

### Feed / browse (strong, recently redesigned)
- `apps/web/app/feed/page.tsx` gates on auth + `dating_enabled` + verification, calls `browseFeed` → RPC `browse_feed_for_viewer`, renders `SwipeDeck`.
- `SwipeDeck.tsx` is a real framer-motion swipe deck: drag/rotate/fly-off, like/nope tints + stamps, peek cards, button fallback, keyboard, reduced-motion, tap-to-open detail, "N left" counter. Swipes persist via `recordSwipe` → `record_swipe`.
- `NightCard.tsx` redesigned photo-leads: full-bleed cover + bottom scrim + white drop-shadow title (the dark-title-unreadable bug is FIXED). Vibe tags render as sticker chips. Cover always resolves via `coverImageForNight` (`apps/web/lib/place-image.ts`) with verified on-disk fallbacks.
- Ambient audio rebuilt (`useAmbientDeck.ts`): real Web Audio crossfade deck, iOS-safe unlock, decode cache + preload, shipped fallback bed (`/ambient/*`). Resolved server-side in `browse_feed_for_viewer`.
- `NightDetailSheet.tsx` is a rich blind-safe sell surface: `get_night_detail` RPC, hero + chip facts (when/distance/$pp/who-pays/vibe/duration), hook, vibe stickers, per-stop photo timeline with cost + Google-Maps name links. Graceful fallback to the blind summary on RPC failure.
- `BottomTabShell.tsx` gives feed a way forward/back. Loading skeleton + tier-aware empty state exist.

### Date detail
- Feed→detail continuity works (tap passes the same `FeedNight` straight in). Blind contract correctly enforced end-to-end (RPC scrubs identity + `reservation_url`, authenticated-only, excludes own/unapproved). Stop timeline + chip facts render from real fields.

### Host identity / reveal
- Binary RLS reveal gate works: `match_reveal_allowed` / `_pair` open the counterpart's `profiles` row once an active/accepted offer or active/completed lock exists (`20260527126500`, `126600`, hardened `127700`). Host pre-offer disclosure: `match_host_can_see_candidate` lets a creator read a queued candidate's full profile.
- Post-lock reveal UI: `/matches/[lockId]` → `RevealModal` → `ProfileCard` (name, age, place, pronouns, photo carousel, vibe chips, prompts). Candidate offer screen `/offers/[offerId]` reveals host name/age/city/clear photo pre-lock.
- Blur pipeline exists: `supabase/functions/generate-blur` produces `blurred_photo_url` / `blurred_path`, invoked at onboarding + photo replace.

### Business objects / venues
- Venues are first-class CONTENT: rich `/places/[slug]` page (name, address, hours, open-now, phone, website, reservation, reviews, rating, photo gallery, maps, JSON-LD), browseable `/places` catalog, deep Google enrichment on the `places` table. Planner `StopCard` links venue titles to `/places/[slug]`. Custom-venue submission queue + admin venue QA dashboard exist.

### Filters
- Entry point only: a gear button (`SwipeDeck.tsx`) opens `FilterSheet.tsx` — an explicitly-labeled placeholder shell.

### Navigation
- `BottomTabShell` is the sole Tier-1 nav: discover→`/feed`, dates→`/my-nights`, +→`/create`, inbox→`/inbox`, profile→`/home`. Mounted on only 5 surfaces (feed, my-nights, inbox, home, account).

### Creators
- Two-door entry: Door 1 "build it for me" (`/create/generate` → AI funnel → `PublishToFeedButton`), Door 2 "start from scratch" (`create_blank_itinerary` → `/plans/[id]/edit`). `ItineraryEditor` supports title/reorder/rename/retime/cost/what-to-do/add-remove stop + custom Google-Places venue. Richer publish surface at `/nights/new` (`PostNightForm`): plan picker, datetime scheduling, ambient-sound picker. `post_night` forks the itinerary into a host-owned copy.

### Host marketplace ("who's interested") — most complete dating surface
- `/dates/[slug]/interested` → `InterestedList`: draggable shortlist (rank, optimistic persist), new-interest list (tap-to-shortlist), realtime new-interest append, load-more. Shortlist → make-offer (`MakeOfferModal`) → candidate accept/pass/withdraw (`/offers/[offerId]`) → lock. Reciprocal double-host resolution (`/reciprocal/[pairId]`). All wired through real RPCs + edge functions.

### Messaging — engine real, wiring absent
- Unified `/inbox` (activity + threads), `ThreadList`/`ThreadRow`, `Conversation.tsx` (optimistic send, realtime, mark-read, report-message), composer, combined unread badge. Chat engine is solid.

### Profile — split and mislabeled
- Real editor at `/account/profile` (`ProfileEditor`: name, neighborhood, bio, instagram, vibe_tags, photo gallery + blur, dynamic prompts, expanded fields). Read-only `ProfileCard` only in the reveal modal. Notification prefs at `/account/notifications`. Account hub at `/account`. Dating preferences (gender/age/distance/dealbreakers) captured at onboarding.

### State machine (back half missing)
- Forward path real: night `seeking` (via `post_night`) → `matched` (accept/lock) → `cancelled` (post-match lock cancel only); `matched`→`seeking` revert on non-safety cancel. Queue: interested→shortlisted→offer_active→locked plus passed/expired/standby. Offers: active→accepted/passed/expired with single-active-offer invariant. Auto-roll (standby promotion) real. Rating capture (`match_ratings`) write path works.

## Section B — Missing MVP functionality (Critical / High / Medium / Low)

### CRITICAL
1. **Progressive reveal does not exist — it is a binary on/off gate.** Vision is pre-match blurred/limited → match partial → threshold full. Reality: browse shows ZERO host identity; the instant an offer/lock exists you get the FULL clear profile. No "partial" tier, no threshold event. The built blur pipeline (`generate-blur`, `blurred_photo_url`/`blurred_path`) is orphaned — no screen ever displays a blurred photo, no `signBlurredUrls()` helper exists. (`20260527126500`, `apps/web/lib/after5/photos.ts`, `generate-blur/index.ts`)
2. **Feed carries no host presence at all** — not even the "limited" tier. `FeedNight` has no host id/name/photo; the detail sheet states "the host stays anonymous until you match." The headline "blurred face, experience leads" promise is not even partially representable. (`packages/api-client/src/feed.ts`, `NightDetailSheet.tsx:317`)
3. **Lock never reaches `completed`.** No RPC/job transitions `locks.status` active→completed; `close_rating_window` only stamps `rating_closed_at`. A successful date lives forever as `active`. The core loop literally never terminates. (`20260527127200_p5_job_rpcs_backfill.sql:71-95`)
4. **`/matches/[lockId]` shows the person but NOT the plan/venues.** The night that was the entire basis of the match — its itinerary, stops, venues — is invisible once matched. Breaks "every match already has a real plan attached." (`apps/web/app/matches/[lockId]/page.tsx:29-37`, `LockDetail.tsx`)
5. **Hosts get NO notification when someone swipes right.** `match_ingest_interest` dispatches nothing; `interest_received` is defined-but-never-dispatched. The supply side is blind to demand — the loop only closes if the host happens to open `/my-nights`. (`20260527126200_p5_shortlist.sql`, `notif-map.ts:77`)
6. **Dating preferences are write-once.** Age range, distance, gender, dealbreakers are set only at `/onboarding/preferences`, with no link back from any account/settings surface. Core matching settings cannot be changed after signup. (`apps/web/app/onboarding/preferences/page.tsx`)
7. **Conversation is a hard dead-end + chat→profile/night is impossible.** `Conversation.tsx` has no back button, no `BottomTabShell`, and no link to the counterpart profile, the night, or the match. A user building rapport cannot see who they are talking to or recall the plan. The header name looks tappable but does nothing. (`apps/web/app/messages/[threadId]/Conversation.tsx:151-178`)
8. **`/matches/[lockId]` and `/matches` are nav-orphaned.** The bottom-nav "dates" tab points to `/my-nights` (host posts), so the user's actual locked dates list (`/matches`) is not in the primary nav. Match detail has no bottom nav and no back. (`BottomTabShell.tsx:22`)

### HIGH
9. **Profile tab points to the wrong screen (ISSUE #15).** `BottomTabShell.tsx:24` and `UserMenu.tsx:29` label `/home` as "profile", but `/home` is the `FirstSessionHome` marketing teaser (how-it-works explainer, example gallery, referral). The real profile is buried at `/account/profile`.
10. **No real feed filters.** `FilterSheet` is a placeholder; the day/time scope toggle is a no-op that only changes a heading. `browse_feed_for_viewer` accepts no filter params. No max-price/max-distance/host-gender/vibe/who-pays/time filtering exists. `profiles.feed_filters` and per-date targeting columns (`target_genders`, `target_age_range`, `search_radius_km`) do not exist. (`FilterSheet.tsx`, `SwipeDeck.tsx:33-53`, `20260602120400`)
11. **No host EDIT of a posted night.** No `update_night` RPC, no edit UI. A typo'd time/wrong venue cannot be corrected. (only service-role seed scripts touch the row)
12. **No host PRE-MATCH cancel/unpublish/delete.** A `seeking` night cannot be taken down by its creator; `cancel_lock` requires an existing lock. (`creator_pre_lock` reason is only reachable post-match)
13. **No host reject/dismiss of a candidate.** No `reject_candidate` RPC, no decline action. The new-interest list grows unboundedly; the marketplace models "accept" but not "reject."
14. **Ratings have no consumer.** `reliability_score` is read (badge) but never computed from `match_ratings`. The entire trust loop is a dead-end write. (`20260525122700_p1_badge_view.sql`)
15. **No reveal at the offer/lock stage that surfaces the plan/venues; reveal is photo-led.** `InterestedList`/`OfferDetail` lead with `clear_photo_url` — the opposite of "swipe on the date, not the face." The detail sheet's venues vanish post-match.
16. **`/account/notifications` is orphaned** — no inbound link anywhere, no nav chrome, no back. URL-only and traps the user.
17. **No self-profile VIEW** ("preview my profile as others see it"). `ProfileCard` only renders in the reveal modal.
18. **Offer delivery to the candidate depends on notifications + a best-effort email the edge runtime can't send (blank RESEND key).** If notifications aren't surfaced, the candidate has no path to `/offers/[id]` (`notif-map.ts` is the only nav). (`match.ts:111`)
19. **`day_of_reconfirm` / `safety_checkin` flows never run.** Handlers exist in `process-jobs/handlers.ts` but nothing enqueues them, and `match_reconfirm_timeout` / `match_stale_date_close` / `match_expire_pending` / `process_deletion` RPCs DO NOT EXIST — if enqueued they would poison-loop.
20. **No `completed`/expiry sweep for past-dated nights.** A `seeking` night whose `starts_at` passed stays `seeking` forever; no cron sweeps it. Stale-night accumulation.
21. **Door-2 canvas has no publish affordance.** `ItineraryEditor` saves but offers no path to `/nights/new`. Scratch builders are stranded; the two doors are asymmetric (Door 1 has `PublishToFeedButton`).
22. **No cover-image upload + no who-pays/vibe-tags/radius creator controls.** `pay_setting`, `vibe_tags`, `why_note`, `p_venue` all exist server-side but have NO creator UI. Cover is limited to Google stop photos, so scratch nights ship imageless.
23. **`/account/page.tsx` builds a `/plan/i/${id}` link to a route that does not exist** → 404 for slug-less saved plans.
24. **No bottom nav / back on host candidate list and offer active state.** `/dates/[slug]/interested` and `/offers/[offerId]` (active) have no back affordance.

### MEDIUM
25. No real map/route anywhere; the detail-sheet "the route" is decorative (hardcoded pins) while real lat/lng are fetched and discarded. Per-stop "map" links are name text-searches (can deep-link to the wrong venue). (`NightDetailSheet.tsx:290-313`)
26. Feed/detail hero image can differ when `cover_image_url` is null (only the detail path feeds `stops` into the shared resolver).
27. No business-ownership model — `places` has no `owner_id`/claim/merchant concept. Not a two-sided venue marketplace.
28. `/places` + `/places/[slug]` have zero in-app inbound links and funnel to `/create` (legacy planner), away from the dating loop.
29. Feed ordering is purely chronological — no compatibility/vibe/relevance ranking.
30. No human city/area label reaches the card (RPC returns `city_id` only); distance is city-centroid coarse (~0 same-city), so proximity is effectively absent within a city.
31. `no_show` lock status is unreachable (enum exists, no transition sets it).
32. Standby is never surfaced to the candidate as "you're next in line"; candidate cannot withdraw a plain `interested` interest from any UI (no list of their pending interests).
33. No column-level PII projection at the reveal gate (relies on UI voluntarily selecting Tier-3 columns).
34. No profile stats, no post-onboarding verification status panel, no aggregated privacy controls (dating on/off toggle lives in `EnableDatingButton`, not a settings home).
35. No keyset pagination in the feed (static deck of 20; heavy browsers hit empty state prematurely).
36. New-message notification deep-links to `/matches` (a list), not the thread; no leave/mute/block from within a conversation.
37. `PublishToFeedButton` hardcodes date (+2d 18:00), no pay/venue/tags; divergent from `/nights/new` and can't receive a just-generated itinerary by id.

### LOW
38. `host.bio` prop rendered in `OfferDetail` but always `null` (no bio column). Dead UI branch.
39. Loading skeleton models the OLD card layout (visual jump). 40. No archive view / no draft state. 41. Soundtrack picker silently vanishes if the ambient library is empty. 42. `date_match_status` enum value `none` is orphaned. 43. Rank collisions unmanaged server-side. 44. No typing indicators / read receipts.

## Section D — Broken user journeys

1. **Browse → Match (around the experience).** Broken at the reveal premise: the deck carries no blurred/limited host, so "swipe on the date, not the face" is not representable. The day-scope toggle and filters promise narrowing they never deliver; distance/city signals are degraded. (`SwipeDeck.tsx`, `FilterSheet.tsx`, `feed.ts`)
2. **Host → Publish.** Door 2 (scratch) builds a night but the canvas has no publish CTA — host must independently discover `/nights/new`. Generated (Door 1) nights publish with a hardcoded date and no who-pays/venue/tags. Scratch nights ship imageless (no upload, often no stop photos). (`ItineraryEditor.tsx:209-216`, `PublishToFeedButton.tsx`)
3. **Swipe-right → Host notices.** Severed: no `interest_received` dispatch, so the host learns of demand only by manually opening `/my-nights`. (`match_ingest_interest`)
4. **Host → Triage → Reject.** No reject/dismiss path exists; only shortlist or ignore. The new-interest list is append-only.
5. **Offer sent → Host sees the result.** No on-page accept/pass/expire reflection, no withdraw control on the interested list.
6. **Match → back to browsing.** After accepting, the user is pushed to `/matches/[lockId]` (no nav); resuming the feed requires browser-back.
7. **Match → Chat → back to Match.** `LockDetail` "message" opens a tab-less, back-less conversation; no in-UI round trip. Routes through a `/messages` redirect hop.
8. **Chat → Profile.** Impossible. The revealed profile only lives at `/matches/[lockId]`; the conversation has no link to it (and doesn't even know the lockId).
9. **Chat → Night / plan.** Impossible from the conversation — breaks "every match has a plan attached" at the exact moment the user wants it.
10. **Profile → Night** and **Night → Profile/Chat.** `LockDetail` doesn't link to the night; `/offers/[offerId]` has zero links to the conversation or night plan.
11. **"Dates" tab → your matched dates.** Lands on `/my-nights` (host posts), never `/matches`.
12. **"Profile" tab → your profile (ISSUE #15).** Lands on the `/home` marketing teaser, not `/account/profile`.
13. **Edit matching preferences post-signup.** Impossible — `/onboarding/preferences` is unlinked after onboarding.
14. **Go on the date → mark it done → review → reliability.** Broken at the "date" boundary: nothing marks a date completed, the lock can't leave `active`, ratings feed nothing, `reliability_score` never recomputes.
15. **Post a night → fix a typo / cancel it pre-match.** No edit, no unpublish, no delete path.
16. **Safety: day-of reconfirm + post-date check-in.** Never fires (no producers; RPCs missing).
17. **Feed night → venue business page.** The richest venue surface (`/places/[slug]`) is walled off from the dating loop (blind contract strips `place_slug`, never restored post-match).

**17 broken journeys.**

## Synthesis notes & resolved contradictions
