# P6 — Chat — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the messaging subsystem for the locked/offer flow on Supabase Realtime — one private chat thread per offer (and the lock it becomes), readable/writable by exactly the two parties, that opens **only to the active offer-holder** per the P5 state machine and persists across the lock. Includes: retention policy, media/attachment handling (Storage + size/type limits), read state/receipts, **block propagation** (a block hides the thread and freezes new messages), in-thread **report** (writing P0 `reports`), a concrete decision on the **"locked near-strangers / little rapport"** tension (minimum-exchange gate before a lock can be finalized), and **off-platform-contact detection** (flag shared phone/socials patterns → soft warning).

**Architecture:** A `chat_threads` table (one row per `date_instance`, owning a `creator_id`/`candidate_id` pair) and a `chat_messages` table. The Realtime transport is one channel per thread, named `chat_${thread_id}`, scoped by Postgres-changes filtered on `thread_id` + RLS. Threads are created/opened by a **SECURITY DEFINER** RPC driven by the P5 offer transition (only the active offer-holder), never by direct client insert. Message sends go through a `send_message` RPC (SECURITY DEFINER) that enforces the open/blocked/closed gate, runs off-platform-contact detection, and writes the row — so RLS on the table itself can stay simple (party-read, no direct insert). The **min-rapport gate** is a DB function `chat_lock_ready(thread_id)` that the P5 `confirm_lock` transition must call before flipping an offer to `locked`. Attachments live in a private Storage bucket `chat-media` with RLS-style Storage policies keyed to thread membership; messages reference an `attachment_path`.

**Tech Stack:** Supabase Postgres (migrations in `supabase/migrations/`), RLS with `auth.uid()`, Realtime (`supabase_realtime` publication + per-thread channel), Storage (private bucket + object policies), one Edge Function (`chat-attachment-sign`, Deno) for signed-upload URLs with type/size pre-checks, TypeScript helpers in `packages/api-client` (vitest), psql invariant/RLS tests in `supabase/tests/`.

**Source docs:** spec `docs/superpowers/specs/2026-05-25-experience-first-dating-core-loop-design.md` (§7.2 reveal/chat, §8 trust/safety); roadmap `docs/superpowers/plans/2026-05-25-experience-first-dating-implementation-roadmap.md` (P6 scope + Closes); foundation `docs/superpowers/plans/2026-05-25-p0-data-model.md` (`offers`, `locks`, `queue_entries`, `blocks`, `reports`, `audit_log`, `profiles`, `date_instances`).

**Dependency note (P5):** P5 owns the offer/lock state machine and is not yet written as a detailed plan. P6 depends on two P5 contracts and **defines them as named hooks** so P5 can wire them without P6 rework:
1. When an offer becomes `offer_active` for `(date_instance, candidate)`, P5 calls `open_chat_thread(p_date_instance_id, p_candidate_id)` (Task 3). When that offer passes/expires (and no lock formed), P5 calls `close_chat_thread(...)`. When it locks, P5 calls `promote_chat_thread_to_lock(...)`.
2. P5's `confirm_lock` transition MUST call `chat_lock_ready(p_thread_id)` (Task 9) and refuse to lock if it returns false. This is the min-rapport gate.
If P5 lands first, reconcile these names against its RPCs; if P6 lands first, these functions are the source of truth.

**Conventions (follow exactly, mirrors P0):** migration filenames `YYYYMMDDHHMMSS_snake_description.sql`; enable RLS on every table; create policies idempotently with `do $$ begin create policy … exception when duplicate_object then null; end $$;`; attach `set_updated_at()` to tables with `updated_at`; `auth.uid()` in policies; uuid PKs via `gen_random_uuid()`; SECURITY DEFINER functions set `search_path = public`; all status transitions reuse the P0 `log_status_transition()` audit trigger where a `status` column exists.

**Local test loop (mirrors P0):** `supabase db reset` (applies all migrations + seeds) then run a psql test:
`psql postgresql://postgres:postgres@127.0.0.1:54322/postgres -v ON_ERROR_STOP=1 -f <test.sql>`
psql tests use `DO $$ … END $$;` blocks that `RAISE EXCEPTION` on wrong behavior (clean exit = PASS, any raise = FAIL) and `ROLLBACK` their fixtures. Put them in `supabase/tests/`. TS tests use vitest (Task 12 introduces the runner since the repo has none yet).

## Key decisions (locked for this phase)

- **Min-rapport rule (the "locked near-strangers" tension):** Require a **minimum two-sided exchange before a lock can be confirmed**. Concretely: `chat_lock_ready` returns true only when **each party has sent at least 2 non-attachment messages** (≥4 total, ≥2 from each side) **OR** the candidate has explicitly tapped a **"skip chat, lock anyway"** confirm that writes a `lock_ready_override` row (mutual — both must tap to override). Default path is messages; override exists so a genuinely keen pair is never trapped. Rationale vs the alternative (pre-lock structured prompts): the spec already opens a real chat at offer (§7.2), so a thin message-count gate reuses existing surface, needs no new prompt UI, and is enforceable purely in the DB at the P5 lock transition. We pick **minimum-exchange + mutual override**, not structured prompts.
- **Retention policy (concrete):** Messages persist for the **life of the relationship plus a fixed tail**: (a) while an offer is `active` or a lock is `active`/`completed`, messages are retained; (b) if an offer passes/expires **without** a lock, the thread is marked `closed` and its messages are **hard-deleted by a retention job 7 days after close** (transport-history grace so the late-reveal/withdraw flow isn't jarring, then gone — matches the spec's "reveal auto-revoked on pass/expire"); (c) a `completed` lock's thread is **archived read-only** and messages **hard-deleted 30 days after the date's `starts_at`**; (d) a thread touched by a **block or a safety report is frozen and exempt from auto-deletion** (legal-hold for moderation, finalized in P9). Deletion is performed by a `purge_expired_chat()` function invoked by the P2 job runner; P6 ships the function + a `chat_threads.purge_after` column it sets, and a psql test proving the function deletes only eligible threads.
- **Off-platform-contact detection:** `send_message` runs the message body through `detect_offplatform_contact(text)` (phone, @handles, "insta/snap/whatsapp/telegram/cashapp/venmo" keywords, raw URLs, spelled-out digits like "five-five-five"). On a hit it does **not block** the message; it sets `chat_messages.contact_flagged = true` and the client renders a **soft warning** ("Keep chatting here until you meet — it's safer and reportable"). Repeated flags feed P8 anti-abuse later. We flag, we don't censor.
- **Transport:** Postgres-changes Realtime on `chat_messages` filtered by `thread_id`, one channel `chat_${thread_id}`; presence/typing is optional polish (P11), not P6.
- **Reveal-revocation reality:** chat content already sent is retained per the rules above (we cannot un-send), but the thread becomes **non-writable and hidden from the candidate** the instant the offer is no longer theirs or a block lands. This is the honest version of "reveal revoked" (the spec's "reveal revocation is fiction" finding): future access is cut; past transcript is purged on the retention timer.

```sql
-- supabase/migrations/20260525130000_p6_chat_threads.sql
-- One chat thread per scheduled date instance. Created when an offer goes active
-- (P5 calls open_chat_thread). Persists through a lock; closes on pass/expire.
create type chat_thread_status as enum ('open','closed','archived','frozen');

create table if not exists chat_threads (
  id uuid primary key default gen_random_uuid(),
  date_instance_id uuid not null references date_instances(id) on delete cascade,
  creator_id uuid not null references profiles(id) on delete cascade,
  candidate_id uuid not null references profiles(id) on delete cascade,
  offer_id uuid references offers(id) on delete set null,
  lock_id uuid references locks(id) on delete set null,
  status chat_thread_status not null default 'open',
  opened_at timestamptz not null default now(),
  closed_at timestamptz,
  -- Retention: when set and in the past, purge_expired_chat() hard-deletes messages.
  -- Null = not scheduled for purge (open/active threads, or frozen by block/report).
  purge_after timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique (date_instance_id),
  check (creator_id <> candidate_id)
);
create index if not exists chat_threads_creator_idx on chat_threads(creator_id);
create index if not exists chat_threads_candidate_idx on chat_threads(candidate_id);
create index if not exists chat_threads_purge_idx on chat_threads(purge_after)
  where purge_after is not null;
create trigger set_chat_threads_updated_at before update on chat_threads
  for each row execute function set_updated_at();

alter table chat_threads enable row level security;
do $$ begin
  -- Only the two parties read the thread, and only while it is not closed/frozen
  -- to *them*. Closed threads stay readable to both during the retention tail;
  -- block-hiding is handled in send_message + a candidate-visibility predicate.
  create policy "chat_threads_party_read" on chat_threads for select
    using (creator_id = auth.uid() or candidate_id = auth.uid());
exception when duplicate_object then null; end $$;
-- No insert/update policy: threads are created/managed by SECURITY DEFINER RPCs only.

-- Audit thread lifecycle transitions via the P0 generic trigger.
create trigger audit_chat_threads after insert or update on chat_threads
  for each row execute function log_status_transition();
```

```sql
-- supabase/migrations/20260525130100_p6_chat_messages.sql
create table if not exists chat_messages (
  id uuid primary key default gen_random_uuid(),
  thread_id uuid not null references chat_threads(id) on delete cascade,
  sender_id uuid not null references profiles(id) on delete cascade,
  body text,                          -- null only when attachment-only
  attachment_path text,               -- storage object path in bucket 'chat-media'
  attachment_type text,               -- mime, e.g. 'image/jpeg'
  contact_flagged boolean not null default false,  -- off-platform detection hit
  is_system boolean not null default false,        -- system notices (e.g. "chat opened")
  read_at timestamptz,                -- set when the *other* party marks read
  created_at timestamptz not null default now(),
  check (body is not null or attachment_path is not null)
);
create index if not exists chat_messages_thread_created_idx
  on chat_messages(thread_id, created_at);
create index if not exists chat_messages_unread_idx
  on chat_messages(thread_id) where read_at is null;

alter table chat_messages enable row level security;
do $$ begin
  -- Both parties of the thread may read messages. Block-hiding is enforced by
  -- a NOT EXISTS blocks check so a blocked counterparty's messages disappear.
  create policy "chat_messages_party_read" on chat_messages for select using (
    exists (
      select 1 from chat_threads t
      where t.id = chat_messages.thread_id
        and (t.creator_id = auth.uid() or t.candidate_id = auth.uid())
        and not exists (
          select 1 from blocks b
          where (b.blocker_id = auth.uid()
                 and b.blocked_id in (t.creator_id, t.candidate_id))
             or (b.blocked_id = auth.uid()
                 and b.blocker_id in (t.creator_id, t.candidate_id))
        )
    )
  );
exception when duplicate_object then null; end $$;
-- No INSERT policy: all writes go through send_message() (SECURITY DEFINER, Task 4).
-- UPDATE allowed only to mark-read via mark_thread_read() RPC (Task 6); no direct UPDATE policy.

-- Add to the Realtime publication so clients can subscribe to chat_${thread_id}.
alter publication supabase_realtime add table chat_messages;
```

```sql
-- supabase/migrations/20260525130200_p6_thread_rpcs.sql
-- Opened by P5 when an offer goes active. SECURITY DEFINER so it can write the
-- thread row (no client insert policy). Idempotent: returns the existing open
-- thread for the instance if one exists for the same candidate.
create or replace function open_chat_thread(p_date_instance_id uuid, p_candidate_id uuid)
returns uuid
language plpgsql security definer set search_path = public as $fn$
declare v_creator uuid; v_offer uuid; v_thread uuid; v_existing record;
begin
  select creator_id into v_creator from date_instances where id = p_date_instance_id;
  if v_creator is null then raise exception 'date_instance % not found', p_date_instance_id; end if;

  -- Must correspond to the currently active offer for this candidate (offer-holder ONLY).
  select id into v_offer from offers
   where date_instance_id = p_date_instance_id
     and candidate_id = p_candidate_id
     and status = 'active'
   limit 1;
  if v_offer is null then
    raise exception 'no active offer for candidate % on instance %', p_candidate_id, p_date_instance_id;
  end if;

  select * into v_existing from chat_threads where date_instance_id = p_date_instance_id;
  if found then
    if v_existing.candidate_id <> p_candidate_id then
      -- Seat rolled to a new candidate: re-point the thread, close prior history's write path.
      update chat_threads
         set candidate_id = p_candidate_id, offer_id = v_offer,
             status = 'open', closed_at = null, purge_after = null
       where id = v_existing.id;
    end if;
    return v_existing.id;
  end if;

  insert into chat_threads (date_instance_id, creator_id, candidate_id, offer_id, status)
  values (p_date_instance_id, v_creator, p_candidate_id, v_offer, 'open')
  returning id into v_thread;

  -- System opener message so the chat isn't empty.
  insert into chat_messages (thread_id, sender_id, body, is_system)
  values (v_thread, v_creator, 'You''re the active pick for this night — say hi.', true);
  return v_thread;
end $fn$;

-- Closed by P5 on offer pass/expire when no lock formed. Schedules a 7-day purge tail.
create or replace function close_chat_thread(p_date_instance_id uuid)
returns void
language plpgsql security definer set search_path = public as $fn$
begin
  update chat_threads
     set status = case when status = 'frozen' then 'frozen' else 'closed' end,
         closed_at = now(),
         -- Frozen threads (block/report) are exempt from purge: leave purge_after null.
         purge_after = case when status = 'frozen' then purge_after
                            else now() + interval '7 days' end
   where date_instance_id = p_date_instance_id;
end $fn$;

-- Promoted by P5 on lock. Attaches lock_id, archives read-only after the date,
-- and schedules a 30-day post-date purge tail (set at completion in Task 7's trigger).
create or replace function promote_chat_thread_to_lock(p_date_instance_id uuid, p_lock_id uuid)
returns void
language plpgsql security definer set search_path = public as $fn$
begin
  update chat_threads
     set lock_id = p_lock_id, status = 'open', closed_at = null, purge_after = null
   where date_instance_id = p_date_instance_id;
end $fn$;

revoke all on function open_chat_thread(uuid,uuid) from public, anon, authenticated;
revoke all on function close_chat_thread(uuid) from public, anon, authenticated;
revoke all on function promote_chat_thread_to_lock(uuid,uuid) from public, anon, authenticated;
-- Executable only by service_role / P5 SECURITY DEFINER transitions.
```

```sql
-- supabase/migrations/20260525130300_p6_send_message.sql
-- Heuristic off-platform-contact detector. Returns true on a likely attempt to
-- move the conversation off-platform (phone, @handles, socials/payment apps, urls).
-- Intentionally lenient on false positives — it only triggers a soft warning, never a block.
create or replace function detect_offplatform_contact(p_body text)
returns boolean
language plpgsql immutable set search_path = public as $fn$
declare v text;
begin
  if p_body is null then return false; end if;
  v := lower(p_body);
  -- 7+ digit run, or NA phone shapes with separators (250-555-0143, (250) 555 0143)
  if v ~ '(\d[\s.\-]?){7,}' then return true; end if;
  -- spelled-out digit runs ("five five five")
  if v ~ '(zero|one|two|three|four|five|six|seven|eight|nine)([\s\-]+(zero|one|two|three|four|five|six|seven|eight|nine)){4,}' then return true; end if;
  -- @handles
  if v ~ '@[a-z0-9._]{3,}' then return true; end if;
  -- raw urls / domains
  if v ~ '(https?://|www\.|[a-z0-9.\-]+\.(com|net|io|co|me|app)\b)' then return true; end if;
  -- social/payment app keywords near a handle-y context
  if v ~ '\m(insta(gram)?|snap(chat)?|whats[\s]?app|telegram|signal|kik|cash\s?app|venmo|paypal|tiktok|number|cell|text\s+me|call\s+me|dm\s+me)\M' then return true; end if;
  return false;
end $fn$;

-- The single write path for chat. Enforces: sender is a party, thread is writable
-- to them (open + lock active where applicable), no block between the pair.
-- Runs off-platform detection and stamps contact_flagged. Returns the new message id.
create or replace function send_message(
  p_thread_id uuid,
  p_sender_id uuid,
  p_body text,
  p_attachment_path text,
  p_attachment_type text
)
returns uuid
language plpgsql security definer set search_path = public as $fn$
declare t record; v_id uuid; v_flag boolean;
begin
  select * into t from chat_threads where id = p_thread_id;
  if not found then raise exception 'thread % not found', p_thread_id; end if;

  -- sender must be one of the two parties
  if p_sender_id not in (t.creator_id, t.candidate_id) then
    raise exception 'sender % not a party of thread', p_sender_id;
  end if;

  -- thread must be writable: open only (closed/archived/frozen are read-only)
  if t.status <> 'open' then
    raise exception 'thread % not open for writing (status %)', p_thread_id, t.status;
  end if;

  -- no block in either direction between the pair
  if exists (
    select 1 from blocks b
    where (b.blocker_id = t.creator_id and b.blocked_id = t.candidate_id)
       or (b.blocker_id = t.candidate_id and b.blocked_id = t.creator_id)
  ) then
    raise exception 'thread blocked; messaging disabled';
  end if;

  -- content presence
  if p_body is null and p_attachment_path is null then
    raise exception 'empty message';
  end if;
  if p_body is not null and length(p_body) > 4000 then
    raise exception 'message too long';
  end if;

  v_flag := detect_offplatform_contact(p_body);

  insert into chat_messages (thread_id, sender_id, body, attachment_path, attachment_type, contact_flagged)
  values (p_thread_id, p_sender_id, p_body, p_attachment_path, p_attachment_type, v_flag)
  returning id into v_id;

  update chat_threads set updated_at = now() where id = p_thread_id;
  return v_id;
end $fn$;

revoke all on function send_message(uuid,uuid,text,text,text) from public;
grant execute on function send_message(uuid,uuid,text,text,text) to authenticated;

-- wrapper passes the session user. A future hardening (P8) can derive sender from
```

```sql
-- When a block lands between two users, freeze any thread between them: no further
-- writes (send_message rejects non-open), and the threads list hides it (Task 5 view).
-- Frozen = exempt from auto-purge (moderation hold).
create or replace function freeze_threads_on_block() returns trigger
language plpgsql security definer set search_path = public as $fn$
begin

     set status = 'frozen', closed_at = coalesce(closed_at, now()), purge_after = null
   where status <> 'frozen'
     and ((creator_id = new.blocker_id and candidate_id = new.blocked_id)
       or (creator_id = new.blocked_id and candidate_id = new.blocker_id));

-- When a lock completes/cancels, archive its thread read-only and schedule purge.
-- Completed: purge 30 days after the date's starts_at. Cancelled: purge 7 days after now.
create or replace function archive_thread_on_lock_end() returns trigger
language plpgsql security definer set search_path = public as $fn$
declare v_starts timestamptz;
begin
  if new.status in ('completed','cancelled','no_show')
     and (tg_op='INSERT' or new.status is distinct from old.status) then
    select starts_at into v_starts from date_instances where id = new.date_instance_id;
    update chat_threads
       set status = case when status='frozen' then 'frozen' else 'archived' end,
           purge_after = case
             when status='frozen' then purge_after  -- moderation hold: keep null
             when new.status='completed' then v_starts + interval '30 days'
             else now() + interval '7 days'
           end
     where date_instance_id = new.date_instance_id;
  end if;
  return new;
end $fn$;
create trigger locks_archive_chat after insert or update on locks
```

```sql
-- DECISION: a lock cannot be confirmed until the pair has minimally connected.
-- Default path: each party has sent >= 2 non-system, non-attachment-only text messages.
-- Override path: BOTH parties tap "lock anyway" (mutual), recorded here.
-- P5's confirm_lock transition MUST call chat_lock_ready() and refuse if false.

create table if not exists lock_ready_overrides (
  thread_id uuid not null references chat_threads(id) on delete cascade,
  user_id uuid not null references profiles(id) on delete cascade,
  created_at timestamptz not null default now(),
  primary key (thread_id, user_id)
);
alter table lock_ready_overrides enable row level security;
do $$ begin
  create policy "lock_ready_overrides_party_read" on lock_ready_overrides for select using (
    exists (select 1 from chat_threads t where t.id = thread_id
            and (t.creator_id = auth.uid() or t.candidate_id = auth.uid()))
  );
exception when duplicate_object then null; end $$;

    raise exception 'user % not a party', p_user_id;

  if not found then return false; end if;

  select
    count(*) filter (where sender_id = t.creator_id),
    count(*) filter (where sender_id = t.candidate_id)
    into n_creator, n_cand
  from chat_messages
  where thread_id = p_thread_id
    and is_system = false
    and body is not null;        -- attachment-only messages don't count toward rapport

  if n_creator >= 2 and n_cand >= 2 then return true; end if;

  select count(distinct user_id) into n_override
    from lock_ready_overrides where thread_id = p_thread_id;
  return n_override >= 2;
end $fn$;
```

```sql
-- Retention purge. Hard-deletes messages (and their storage objects) for threads
-- whose purge_after has passed. Frozen threads (block/report) have purge_after=null
-- and are therefore never purged here. Returns rows deleted. Invoked by the P2 job runner.
create or replace function purge_expired_chat()
returns int
language plpgsql security definer set search_path = public, storage as $fn$
declare v_n int;
begin
  -- delete storage objects for eligible threads first
  delete from storage.objects o
   using chat_threads t
   where o.bucket_id = 'chat-media'
     and (storage.foldername(o.name))[1] = t.id::text
     and t.purge_after is not null
     and t.purge_after < now()
     and t.status <> 'frozen';

  delete from chat_messages m
   using chat_threads t
   where m.thread_id = t.id
     and t.purge_after is not null
     and t.purge_after < now()
     and t.status <> 'frozen';
  get diagnostics v_n = row_count;

  -- mark purged threads so we don't reprocess them
  update chat_threads
     set purge_after = null, status = 'closed'
   where purge_after is not null and purge_after < now() and status <> 'frozen';

  return v_n;
```

```ts
// supabase/functions/chat-attachment-sign/index.ts
// Returns a signed upload URL for a chat attachment after validating mime/size and
// confirming the caller is a party of an OPEN thread. The actual object write is
// enforced again by storage policies (Task 10); this gives the client a path + token.
import { serve } from 'https://deno.land/std@0.208.0/http/server.ts';
import { createClient } from 'https://esm.sh/@supabase/supabase-js@2.45.0';
import { corsHeaders } from '../_shared/cors.ts';

export const ALLOWED_MIME = ['image/jpeg', 'image/png', 'image/webp', 'image/gif'];
export const MAX_BYTES = 10 * 1024 * 1024; // 10 MiB, matches bucket file_size_limit

interface AttachmentRequest { thread_id: string; content_type: string; size_bytes: number; }

export function validateAttachmentRequest(b: Partial<AttachmentRequest>):
  { ok: true; req: AttachmentRequest } | { ok: false; error: string } {
  if (!b.thread_id || !/^[0-9a-f-]{36}$/i.test(b.thread_id)) return { ok: false, error: 'bad thread_id' };
  if (!b.content_type || !ALLOWED_MIME.includes(b.content_type)) return { ok: false, error: 'unsupported type' };
  if (typeof b.size_bytes !== 'number' || b.size_bytes <= 0 || b.size_bytes > MAX_BYTES) return { ok: false, error: 'bad size' };
  return { ok: true, req: { thread_id: b.thread_id, content_type: b.content_type, size_bytes: b.size_bytes } };
}

function extFor(mime: string): string {
  return ({ 'image/jpeg': 'jpg', 'image/png': 'png', 'image/webp': 'webp', 'image/gif': 'gif' } as Record<string, string>)[mime] ?? 'bin';
}

serve(async (req) => {
  if (req.method === 'OPTIONS') return new Response('ok', { headers: corsHeaders });
  if (req.method !== 'POST') return new Response('method not allowed', { status: 405, headers: corsHeaders });

  const authHeader = req.headers.get('Authorization');
  if (!authHeader) return new Response(JSON.stringify({ error: 'unauthorized' }), { status: 401, headers: { ...corsHeaders, 'Content-Type': 'application/json' } });

  let body: Partial<AttachmentRequest>;
  try { body = await req.json(); } catch { return new Response(JSON.stringify({ error: 'bad json' }), { status: 400, headers: { ...corsHeaders, 'Content-Type': 'application/json' } }); }

  const v = validateAttachmentRequest(body);
  if (!v.ok) return new Response(JSON.stringify({ error: v.error }), { status: 400, headers: { ...corsHeaders, 'Content-Type': 'application/json' } });

  // Service-role client to (a) verify membership + open status, (b) create signed upload URL.
  const supabase = createClient(Deno.env.get('SUPABASE_URL')!, Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')!);
  // Resolve caller from the forwarded JWT.
  const { data: userData } = await supabase.auth.getUser(authHeader.replace(/^Bearer\s+/i, ''));
  const uid = userData?.user?.id;
  if (!uid) return new Response(JSON.stringify({ error: 'unauthorized' }), { status: 401, headers: { ...corsHeaders, 'Content-Type': 'application/json' } });

  const { data: thread } = await supabase
    .from('chat_threads').select('creator_id,candidate_id,status').eq('id', v.req.thread_id).single();
  if (!thread || thread.status !== 'open' || (thread.creator_id !== uid && thread.candidate_id !== uid)) {
    return new Response(JSON.stringify({ error: 'forbidden' }), { status: 403, headers: { ...corsHeaders, 'Content-Type': 'application/json' } });
  }

  const path = `${v.req.thread_id}/${crypto.randomUUID()}.${extFor(v.req.content_type)}`;
  const { data: signed, error } = await supabase.storage.from('chat-media').createSignedUploadUrl(path);
  if (error || !signed) return new Response(JSON.stringify({ error: 'sign failed' }), { status: 500, headers: { ...corsHeaders, 'Content-Type': 'application/json' } });

  return new Response(JSON.stringify({ path, token: signed.token, signed_url: signed.signedUrl }), {
    headers: { ...corsHeaders, 'Content-Type': 'application/json' },
  });
});
```

> **Client flow note:** the client (a) calls this function → gets `{path, token}`, (b) uploads bytes to Storage with that token, (c) calls `send_message(thread_id, sender, caption_or_null, path, content_type)`. So the message row references the attachment only after a successful upload.

```ts
// Client-side mirror of detect_offplatform_contact for instant soft-warning UX.

export function looksLikeOffPlatformContact(body: string | null): boolean {
  if (!body) return false;
  const v = body.toLowerCase();
  if (/(\d[\s.\-]?){7,}/.test(v)) return true;
  if (/@[a-z0-9._]{3,}/.test(v)) return true;
  if (/(https?:\/\/|www\.|[a-z0-9.\-]+\.(com|net|io|co|me|app)\b)/.test(v)) return true;
```
