# M3.5 — Custom Venue via Google Places Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Let a host add a real venue we don't have in our catalog (a quiet coffee shop, etc.) to their date as an inline stop, via a Google Places search — without auto-adding it to the curated `places` table; instead record it to an admin promotion queue for later curation.

**Architecture:** A Next.js server route `/api/places/search` (Node, reads `process.env.GOOGLE_PLACES_API_KEY` — present in the app env; **NOT** the Supabase edge secret) proxies Google Places (New) Text Search, normalizes results, and degrades to a 503 `{error:'search_unavailable'}` if the key is absent (prod-safe). The `ItineraryEditor` (M3) gains an "add a custom place" flow that searches via the proxy, lets the host pick a result, appends it as an inline `Stop` (`place_id` = `custom:<googleId>`), and records the pick to a new `custom_venue_submissions` table (owner-insert / admin-read RLS) — the promotion queue. The inline custom stop is fine for solo/landing planning and personal dates; the existing `post_night` curated-venue guard already blocks a non-`live` place from being a pinned *dating meetup* venue, so safety holds.

**Tech Stack:** Next.js 15 route handler, Supabase (table + RLS), React 19 (editor add-flow), Tailwind Barbiecore, vitest + Playwright.

**Depends on:** M3 (shipped). `GOOGLE_PLACES_API_KEY` must be in the Next/Vercel env for live search (it's in `apps/web/.env.local`; confirm it's set in Vercel for prod search to work — if not, the route 503s gracefully and the UI says search is unavailable).

### Task 2: Pure normalizer (Google result → inline stop)

**Files:** `apps/web/lib/places/normalize.ts` + `__tests__/normalize.test.ts`.

`googlePlaceToStop(r)` maps a Google Places (New) result to a `Stop` (from `@/lib/itinerary-types`): `place_id = 'custom:' + r.id`, `place_name = r.displayName?.text`, `place_type` from a small `mapType(r.types)` (cafe/restaurant/bar/activity/park → our place_type-ish string; default 'activity'), `address = r.formattedAddress`, `lat = r.location?.latitude`, `lng = r.location?.longitude`, `photo_url` = `buildPhotoUrl(r.photos?.[0]?.name)` (the `https://places.googleapis.com/v1/<name>/media?maxWidthPx=1200&key=...` shape — but DO NOT embed the key client-side; instead set `photo_url` to a server-proxied path OR leave null in v1 and note it), `start_time = '19:00'`, `duration_min = 60`, `estimated_cost_pp = 0`. Also `googlePlaceToSubmission(r, itineraryId)` → the `custom_venue_submissions` insert row. Tests cover field mapping + missing-fields safety + the `custom:` prefix.

NOTE on photo: embedding `GOOGLE_PLACES_API_KEY` in a client `photo_url` would leak it. v1: set `photo_url = null` for custom stops (the editor shows a type fallback), and record `raw` so a server job can fetch the photo at promotion time. State this in the test + a code comment.

### Task 3: `/api/places/search` proxy route

**Files:** `apps/web/app/api/places/search/route.ts` + `route.test.ts`.

POST `{ query: string, lat?: number, lng?: number, radiusKm?: number }`. Auth: `createClient()` (server) → `getUser()`; 401 if anon. If `!process.env.GOOGLE_PLACES_API_KEY` → 503 `{error:'search_unavailable'}`. Else mirror M1's call exactly: POST `https://places.googleapis.com/v1/places:searchText` with `X-Goog-Api-Key` + the same `X-Goog-FieldMask` + body `{ textQuery, maxResultCount: 12, locationBias: { circle: { center: { latitude, longitude }, radius: (radiusKm??25)*1000 } } }` (omit locationBias if no lat/lng). Default center = Kelowna (`49.888, -119.496`). Map each result via `googlePlaceToStop` and return `{ results: Stop[] }`. On Google non-200 → 502 `{error:'search_failed'}`.

Tests (mock `global.fetch` + the server client): (a) anon → 401; (b) no key → 503; (c) with key + mocked Google 200 → returns mapped `results` with `custom:` ids; (d) Google 500 → 502.

- [ ] Steps 1–5: TDD, commit `feat(m3.5): /api/places/search Google Places proxy (graceful 503 without key)`.
