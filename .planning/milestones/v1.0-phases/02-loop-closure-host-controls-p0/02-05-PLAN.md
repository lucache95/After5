<objective>
Wire the E8 demand→supply signal (D-07): dispatch the already-defined-but-never-fired `interest_received` notification from inside `match_ingest_interest`, but ONLY when a genuinely NEW interested candidate is added (`n > 0` — the RPC re-runs on every right-swipe and `ON CONFLICT DO NOTHING`s, so a naive dispatch would spam on re-ingests). Deep-link the notification to that night's `/dates/[slug]/interested` list (fixing the current `notif-map.ts` href which points at `/my-nights`). `interest_received` is already a valid `notification_type` (shipped in `gated_inbox_notification_types.sql`) — NO enum migration needed for E8.

Purpose: The host learns of demand without manually opening `/my-nights`.
Output: One migration (CREATE OR REPLACE match_ingest_interest), one psql test, notif-map href + meta edits, a notif-map/inbox href unit assertion.
</objective>
