<objective>
Build the shared `<DeepRouteHeader>` back-chrome primitive (REQ-E1 / D-07-nav, D-08) and mount it on all 6 deep routes AND every link-less guard/error terminal so the user is never trapped. Back navigation is a **deterministic static `backHref`** (a `next/link` to a sensible parent) — never `history.back()`, because every deep route is a cold-entry point reachable from a notification deep-link or direct URL, where blind back exits the app.

This is an independently-shippable vertical slice: after it lands, a real user who cold-enters any deep route (or hits a guard like "not your match") can always get back to a tab root. Bottom nav stays OFF these routes (D-07-nav) — they are focused flows, not tab destinations.

Purpose: Close the universal-nav-chrome gap (audit C4/C7/C8 confirmed dead-ends + the UNREACHED C2/C3/C5/C6/C9 guard/error terminals) with one primitive, consistently.
Output: `DeepRouteHeader.tsx` (+ test), the header mounted on 6 pages and their guard branches, and an extended route-smoke E2E asserting a back affordance everywhere.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cold-entry URL→deep route | A deep route can be entered directly (notification deep-link/direct URL); each page's `getUser()`→`redirect('/login?next=...')` gate is the boundary. The header adds only navigation, no data. |
| guard branch→back target | Guard `<main>` renders for unauthorized access; the added back link targets a public-within-app, auth-gated tab root. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | DeepRouteHeader title (e.g. counterpart first_name) | mitigate | Title is data the page already fetched under RLS for the authorized viewer; the header only re-renders an already-authorized field. Do not pass any field not already RLS-cleared for that viewer on that page. |
| T-02-02 | Spoofing/Elevation | back target to an unauthorized parent | accept | Back targets are tab roots (`/matches`, `/inbox`, `/my-nights`, `/account`), each independently auth-gated; navigating there grants no access the user lacks. No new exposure. |
| T-02-03 | Denial of Service (UX trap) | link-less guard/error terminals | mitigate | The phase's core fix: every guard/error `<main>` gets the back affordance, removing the trap that previously stranded users (audit C4/C7/C8). |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | Zero new packages (RESEARCH Package Legitimacy Audit "Not applicable"); `lucide-react`/`next/link` already in production. |
</threat_model>
