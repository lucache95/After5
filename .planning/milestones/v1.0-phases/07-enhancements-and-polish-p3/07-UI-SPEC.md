# Phase 7 — UI Design Contract

> Visual and interaction contract for Phase 07 (Enhancements & Polish, P3). Generated by gsd-ui-researcher, verified by gsd-ui-checker. This phase is WIRING + tuning over existing Barbiecore surfaces (mode: mvp), not net-new screens. The contract below pins what each scoped surface must look like and say so the executor implements without design ambiguity.

**Governing doc:** `docs/superpowers/DESIGN-SYSTEM.md` is the source of truth for all tokens, voice, and motion. This spec specializes it for the six scoped surfaces. Where this spec and DESIGN-SYSTEM.md ever appear to conflict, DESIGN-SYSTEM.md wins.

**Scoped surfaces (per CONTEXT D-01..D-03):**
- E20 — real static Mapbox map in the night detail sheet + per-stop coord deep-links
- E21 — matched-night stops link to `/places/[slug]`; retire the `/create` CTA on venue pages; NO `/places` global nav
- E22 — tuned soft-score (ordering only, no UI change beyond order)
- E23 — human `city_name` label on NightCard + finer distance
- E24 — candidate-side standby/waitlist UI ("you're next in line" + withdraw-pending-interest)
- E25 (scoped) — detail-sheet loading skeleton matching the new card + archive view/tab for past nights+matches

## Spacing Scale

The codebase uses Tailwind's default 4px-base scale (`p-5`=20, `gap-4`=16, etc.). Declared multiples-of-4 contract for this phase:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | icon-to-label gaps (`gap-1`), inline chip padding |
| sm | 8px | compact element spacing (`gap-2`, chip rows) |
| md | 16px | default stack gap (`gap-4`), section padding |
| lg | 20-24px | sheet/card body padding (`p-5`), section breaks |
| xl | 32px | layout gaps between major blocks |
| 2xl | 48px | tab-bar / archive-list top breaks |

Exceptions:
- **Tap targets ≥44px** (DESIGN-SYSTEM §4 / CLAUDE.md). The standby withdraw control, the archive tab toggles, and the map button must each present a ≥44px hit area even when the visible chrome is smaller.
- Existing CTA pills run `px-5..px-7 py-3..py-4` (>44px tall) — match those exactly; do not introduce a new button size.

## Typography

Dating-vertical roles (Caprasimo headings, Fredoka body). Existing surfaces already pin these; new surfaces MUST reuse the same classes so the phase reads as one app.

| Role | Size | Weight | Line Height | Token |
|------|------|--------|-------------|-------|
| Display (sheet/card title) | 30-34px | Caprasimo regular (the face is the weight) | ~1.0 (`leading-[1.02]`) | `font-heading text-3xl` / `text-[34px]` |
| Heading (section / standby card title) | 20px | Caprasimo regular | ~1.1 (`leading-tight`) | `font-heading text-xl` |
| Body | 15-16px | Fredoka 400/500 | 1.5 (`leading-relaxed`) | `font-body text-[15px]`/`text-base` |
| Label (chips, meta, section eyebrow) | 11-13px | Fredoka 600 (semibold) | ~1.3 (`leading-snug`) | `font-body text-xs`/`text-[13px] font-semibold` |

Rules:
- **All headlines/subheads/CTAs lowercase** (DESIGN-SYSTEM §2/§3). No exceptions on new copy.
- Section eyebrows ("the route", "your queue") use the existing pattern: `font-body text-[11px] font-bold lowercase tracking-[0.16em] text-shell-ink/50`.
- Exactly 2 weights in play per surface: Fredoka 400/500 for body, Fredoka 600 for labels/CTAs; Caprasimo carries headings (its single weight). Do not add a third weight.

## Color

Three-tier Barbiecore (DESIGN-SYSTEM §1). 60/30/10 split for the Tier-1 shell surfaces this phase touches (standby UI, archive view, detail-sheet chrome). Tier-2 experience surfaces (NightCard, the detail-sheet hero) keep their per-vibe `vibePalette()` palette — that is by design and is exempt from the shell 60/30/10.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `shell.base` `#FAF4EC` | warm-cream app/sheet/archive background |
| Secondary (30%) | `shell.pink` `#FFE5F1` + `shell.ink/5..10` | soft washes, secondary buttons, chip backgrounds, queue-card surfaces |
| Accent (10%) | `shell.accent` `#E0218A` | see reserved-for list |
| Success | `sage` `#5CDBA0` (reserved, NOT yet a token) | "you're next in line" affirmative tick ONLY, if a positive marker is wanted — do not promote unless the standby card actually needs it; default is no sage, accent-on-cream is enough |
| Destructive | none new | this phase has NO red destructive surface. The withdraw-interest control is a low-stakes neutral action (see Copywriting), not a red/danger treatment |

**Accent (`shell.accent`) reserved for:** primary CTA fills ("i'm in", "message {name}"), the curated sticker chip, active/selected states, the map's pin + route-line color, the per-stop `$ pp` price, and the "looks for someone like you" fit pill text. NOT for the withdraw control, NOT for section eyebrows, NOT for generic links, NOT as a background flood.

**Map color note (E20):** the reused `ItineraryMap` hardcodes the planner's terracotta `C2552B` for pins/route. The dating-sheet variant MUST use Barbiecore pink `E0218A` (Mapbox static overlays take a bare hex without `#`). The Mapbox base style stays `mapbox/light-v11` so the warm-cream sheet and the map read as one surface.

**Contrast:** WCAG AA required (CLAUDE.md §a11y). Mind pink-on-pink: the standby card body text stays `shell-ink` / `shell-ink/70` on `shell-base` or `shell-ink/5`, never pink text on `shell.pink`.

## Copywriting Contract

All copy lowercase, dry, Barbiecore, stop-slop (no filler/adverbs/passive), **no em-dashes**. Empty states are funny, not helpful (DESIGN-SYSTEM §3).

| Element | Copy |
|---------|------|
| Primary CTA (standby, withdraw) | `pull my interest` (the withdraw-pending-interest control). Secondary/neutral styling, not accent fill. |
| Standby position line | `you're next in line` when rank = 1; `you're #{rank} in line` for rank > 1. (No apostrophe-curling needed; use a straight or typographic apostrophe consistent with the file.) |
| Standby sub-line | `if the spot opens up, you're up.` (sets the soft, no-promise expectation — promotion logic is deferred, so do NOT promise auto-promotion). |
| Withdraw confirmation | `pull my interest`: a one-line vaul confirm — title `pull your interest?`, body `you'll drop off this night's list. you can always slide back in later.`, confirm button `yep, pull it`. Mirror the existing `LockDetail` flag/cancel vaul pattern (overlay `bg-black/40`, `rounded-t-3xl bg-shell-base`, grab handle). This is low-stakes, NOT red. |
| Map empty / no-coords (E20) | reuse the sheet's existing route copy posture; when no stop has lat/lng, fall back to the existing placeholder block's tone: `stops are a short hop apart` (no broken map, no error chrome). |
| Per-stop map link (E20) | keep the existing `map` link label + `MapPin` icon in `PlanTimeline`; only the href changes (coord deep-link). |
| Venue link affordance (E21, post-match only) | on `LockDetail` stops, the stop name becomes a link to `/places/[slug]`; no new label, the name itself is the affordance. A stop with no catalog slug renders as plain text (graceful degrade, D-01). Do NOT add a "view venue" button. |
| Archive empty state | heading `nothing in the rear-view yet` / body `your past nights and matches land here once they wrap.` |
| Archive tab labels | `upcoming` (default/live) and `archive` (past: completed + expired/cancelled). lowercase. |
| Detail-sheet skeleton caption | none — the skeleton is silent shimmer (matches `feed/loading.tsx` which carries its own caption at the route boundary; the in-sheet skeleton has no text, it just holds the new card's shape while `get_night_detail` resolves). |
| City label (E23) | render `city_name` verbatim, lowercased (the slot already lowercases at `NightCard.tsx:55`). No "in" prefix, no "📍" emoji beyond the existing `MapPin` icon. |

**Retired copy (E21 / D-01):** remove the legacy "build a date here" / create-a-date CTA on `/places/[slug]` venue pages. Do not replace it with a dating-vertical CTA; the venue page becomes a read-only identity surface reached only post-match. No `/places` entry in the bottom-tab shell.

## Per-Surface Interaction Contract

### E20 — real map in the detail sheet
- **Replace** the placeholder route viz at `NightDetailSheet.tsx:264-287` with a real **static** Mapbox image (reuse the `ItineraryMap` pattern: server-rendered PNG, `unoptimized`, no WebGL). This is inherently **reduced-motion friendly** — there is no GL canvas, no auto-pan, no animation. The only motion is the existing lightbox open (`animate-[lightboxIn]`), which already settles under `motion-reduce`.
- The map is **click-to-expand** into the existing full-screen lightbox (Esc to close, body-scroll-lock, backdrop click closes). Tap target: the whole image button (>44px).
- Pins + route line use accent `E0218A`; base style `light-v11`; padding so all pins are framed.
- Renders only when ≥1 stop has lat/lng (planner adds lat/lng per stop via `get_night_detail`). With 0 coords, fall back to the current "short hop apart" placeholder tone — never a broken tile or error.
- The map block keeps its section eyebrow `the route` and sits where the placeholder is today (after the timeline, before the host hint).

### E20 — per-stop coord deep-links
- In `PlanTimeline`, the per-stop `map` link href changes from a name text-search to a coordinate deep-link when `stop.lat`/`stop.lng` are present: `https://www.google.com/maps/search/?api=1&query={lat},{lng}`. Fall back to the existing name-query when coords are absent. Label/icon unchanged. Opens in a new tab (`target="_blank" rel="noopener noreferrer"`, as today).

### E21 — venues into the loop (post-match only)
- On `LockDetail` (post-lock, identity revealed), each stop with a catalog slug links its **name** to `/places/[slug]`. The blind feed `NightDetailSheet` and any offer-stage timeline **must NOT** link to slugs (blind contract — D-01; `PlanTimeline` is shared, so the slug link must be a per-call opt-in prop, default off, enabled only by `LockDetail`).
- Graceful degrade: a stop whose `place_id` isn't in the catalog renders its name as plain text, never a broken link or 404.
- On `/places/[slug]`: retire the "build a date here" → `/create` CTA. No `/places` global/bottom nav.

### E22 — relevance ordering (NO visible UI change)
- Pure backend tune of `browse_feed_for_viewer` ORDER BY. The ONLY user-visible effect is feed card order. No new chrome, no "sorted by relevance" label, no badge. The existing `fit` pill ("looks for someone like you", `NightCard.tsx:107-111`) stays exactly as-is. Keyset cursor stays stable.

### E23 — city label + finer distance
- `NightCard.tsx:54-56` already reads `city_name` defensively and lowercases it; the RPC just needs to return `c.name as city_name`. The card lights up with no component change. Distance keeps `formatDistanceAway` (no UI change); finer source is venue/first-stop coords when available.

### E24 — candidate standby/waitlist UI (net-new surface)
- A **Tier-1 shell** card (warm-cream, NOT a vibe palette — this is app chrome, not an experience surface). Lives on the candidate's interest/standby view.
- Shows the queue position line + soft sub-line (see Copywriting) and the `pull my interest` control.
- `pull my interest` is a **neutral secondary** button: `rounded-full border-2 border-shell-ink/20 text-shell-ink/70` (mirror the existing `cancel this date` button in `LockDetail.tsx:262-268`), NOT an accent fill, NOT red.
- Confirm via vaul bottom sheet (reuse the `LockDetail` flag/cancel sheet pattern). On success: `sonner` toast `pulled. you're off this one.` then refresh.
- Read-path only for rank/status (surface existing `queue_entries.rank`/`status`); do NOT build promotion logic.

### E25 — detail-sheet loading skeleton
- A silent shimmer skeleton shown inside the open drawer while `get_night_detail` is pending (`NightDetailSheet.tsx:85-97` is where detail loads; today it shows the blind summary as fallback). The skeleton must **match the NEW card/sheet shape**: hero block + chip row + hook line + timeline-row placeholders.
- Pure CSS shimmer (`animate-pulse`), **reduced-motion friendly** via `motion-reduce:animate-none` (mirror `feed/loading.tsx` exactly). No spinner. Skeleton surfaces use `bg-shell-ink/10` on `bg-shell-base`/`white`.

### E25 — archive view/tab
- A two-segment toggle on `/my-nights`: `upcoming` (live: seeking/matched/active) and `archive` (past: completed/expired/cancelled). Default to `upcoming`.
- Archive rows reuse the existing `my-nights` `NightCard` row treatment + the existing `lifecycleLabel` corner chip (`done`/`cancelled`). No new card design.
- Empty archive → the funny empty state (see Copywriting). Tab toggles are ≥44px tap targets; active segment uses accent or `shell.pink` active state consistent with the app's existing selected-state convention.
