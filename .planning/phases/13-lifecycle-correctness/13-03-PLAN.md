<objective>
Make the lock-page safety controls persist real records (LIFE-02). Today `LockDetail.confirmFlag()` only sets local state and fires a toast — it calls no RPC and writes no row. And the existing `flag_no_show` RPC (authenticated, either-party, idempotent) has no UI producer. Add a minimal `file_report` DEFINER RPC (reusing the FROZEN `report_reason_category` taxonomy, never inventing reasons), edge-function proxies for both, client wrappers in `match.ts`, and wire LockDetail's "something's wrong" control to write a real `reports` row (target_type='lock') plus a confirm-gated no-show control calling `flag_no_show`.

Purpose: A safety/report tap must leave a verifiable record (a moderator can act on it), and a no-show flag must dent reliability through the real RPC — both behind a confirm step so an accidental tap can't fire.
Output: A file_report migration, two edge fns, two client wrappers, the wired LockDetail UI, and tests (RPC write + RLS deny + UI producer).
</objective>
