<objective>
Close a cancelled lock's chat thread (LIFE-01). Today `match_cancel_lock` flips the lock to `cancelled` and re-rolls the instance but NEVER touches `chat_threads`, so the thread stays `state='promoted'`, `revoked_at IS NULL` — the messageable gate keeps it fully live and "you're locked in." The existing `close_chat_thread(p_offer)` is hard-gated `state='open'`-only and will silently no-op on a promoted thread. Add a `revoke_chat_thread(p_lock)` DEFINER helper keyed by lock_id that sets `state='closed'` + `revoked_at`, call it in BOTH cancel branches, and surface a read-only "this date was cancelled" banner (past messages preserved) for both parties.

Purpose: A cancelled date must not leave a live, messageable, misleading conversation — killing the "you're locked in" state is the non-negotiable core of LIFE-01.
Output: A revoke-on-cancel migration, the cancelled banner UI, a thread-view unit test row, and pgTAP asserting the thread closes on cancel.
</objective>
