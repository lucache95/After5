<objective>
Make standby candidates visible and informed (LIFE-03). Today the candidate's queue surfaces filter `queue_entries` to `status='interested'` only, so `status='standby'` rows are invisible; and the only code that SETS `status='standby'` (`match_autowithdraw_user_conflicts`) dispatches no "you've been bumped" notification. Broaden the two query filters to include standby (keeping the blind-safe `get_night_detail` path), render a standby badge, add a new `standby_bumped` notification enum value + dispatch on bump, and confirm the roll notification (`standby_promoted`, already dispatched in `match_auto_roll`) covers the "offer rolled to you" event.

Purpose: A standby candidate must see the nights they're in line for and be signalled on the two events that change their standby standing.
Output: A notify migration, two broadened SSR filters, a badged StandbyCard, and tests asserting standby rows render with a badge.
</objective>
